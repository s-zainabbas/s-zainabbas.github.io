Daily Dashboard.

The command centre I open every morning: one priority, tasks, today's schedule, a focus timer, habits, notes and an end-of-day journal on a single screen. It works offline, keeps data private, and can sync through my own Google Drive.

Why I rewrote it

Version one was a single 32 KB HTML file. I used it daily, and that's how I found its bugs, some quiet, some that lost data. Patching them one at a time wasn't working, so I rebuilt it in React and TypeScript with tests around the parts that had failed. These are the bugs version two fixed:

Bug in v1Cause and fix
Wrong "today" in many time zonesDates were worked out in UTC, so evening users in the Americas saw tomorrow's tasks. v2 uses local dates throughout, with tests.
Habit streaks never went above 1The streak loop stepped back 86,400,000 days at a time instead of one.
Quick-add tasks disappearedA second script wrote straight to storage and the main app overwrote it on its next save. v2 has one store that owns all data.
"New Day" deleted unfinished tasksRollover now carries unfinished items over and saves the day to a journal.
The focus timer driftedIt counted ticks, which slow down in background tabs. v2 stores timestamps, so it stays accurate across tabs and reloads.
Quick links accepted javascript: URLsLinks are now validated before they're saved.

Data saved by v1 is migrated automatically the first time v2 opens.

Architecture

There's no state library. A small external store built on React's useSyncExternalStore is the single source of truth. It saves with a short debounce, stays in sync across open tabs, and runs versioned migrations when the data format changes.

The hard part: syncing without losing anything

With Drive sync on, the same data can change on a laptop and a phone at once. Overwriting with the newest file would quietly drop edits, so the sync engine runs a three-way merge. It compares the last synced copy with this device and with Drive:

  • Every task, event and habit has a stable ID and a last-changed time, so changes are matched item by item.
  • A change on one side beats unchanged data on the other, so older data never overwrites newer data.
  • Edits to different items, or different fields of one item, are combined. Focus minutes from two devices add up.
  • Deletions leave a tombstone for 90 days, so a deleted task doesn't come back from an older copy.
  • If the same field changed on both sides, the app asks which to keep and uploads nothing until you choose.
  • Before uploading, it checks the Drive file hasn't changed. If another device saved at that moment, it recovers that save from the file's history and merges it.

Sign-in uses Google Identity Services with a short-lived token limited to the app's own hidden Drive folder. There's no client secret and no server. The tests run two simulated devices against an in-memory Drive.

Details I'm proud of

Plain-English quick add

Type Dentist fri 3-4pm and it becomes an event; Call Sam tomorrow !high becomes a task. A live preview shows what was understood before you press Enter.

Job application tracker

Paste a job link and the company, role and location fill in from the Greenhouse, Lever and Ashby APIs. A copy of the description is kept in case the posting comes down.

Keyboard first

⌘K runs any action. Single keys add a task, an event or start a focus session, and ? lists them all.

Accessible by default

Native <dialog> modals with focus trapping and Esc, labelled controls, visible focus rings and reduced-motion support.
